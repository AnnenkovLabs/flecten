# X для ChatGPT

MCP-коннектор для поиска и чтения постов X через свой аккаунт. При подключении ChatGPT открывает страницу входа X и запрашивает разрешения `tweet.read`, `users.read` и `offline.access`. После входа ChatGPT может искать посты и цитировать их по ссылкам X.

Сервер запускается отдельно от Flecten. Токены X не передаются ChatGPT: коннектор выдаёт собственные токены, а учётные данные X сохраняет в зашифрованном файле. Режим работы ограничен чтением. Поиск возвращает до 10 постов за последние 7 дней; чтение по ID или ссылке не ограничено этим поисковым окном. Доступность самих постов и API определяет X.

## Что потребуется

- Bun 1.4 или новее и установленные зависимости репозитория: `bun install`.
- Приложение в [X Developer Console](https://console.x.com/) с OAuth 2.0 и доступом к нужным API. OAuth не отменяет тарифы, оплату запросов и квоты X.
- Стабильный HTTPS-домен коннектора и reverse proxy к локальному порту 8787.
- Возможность добавлять пользовательские MCP-серверы в своём ChatGPT. Доступ зависит от аккаунта и правил рабочего пространства.

## 1. Приложение X

В настройках приложения X включите OAuth 2.0. Тип приложения: **Web App** или другой confidential client с Client Secret. Разрешения: чтение.

Укажите callback URL:

```text
https://ВАШ-ДОМЕН/auth/callback
```

Скопируйте **OAuth 2.0 Client ID** и **Client Secret**. Это не API Key, API Key Secret или Bearer Token. Пользователи коннектора будут входить через X, вручную вводить свой Bearer Token им не потребуется.

## 2. Настройки сервера

Из корня репозитория:

```bash
cp connectors/x-chatgpt/.env.example connectors/x-chatgpt/.env
chmod 600 connectors/x-chatgpt/.env
```

Заполните `X_CONNECTOR_URL`, `X_CLIENT_ID` и `X_CLIENT_SECRET`. Домен в `X_CONNECTOR_URL` должен совпасть с callback URL приложения X. Пути перед `/mcp` не поддерживаются.

Создайте два разных секрета следующей командой, выполнив её дважды:

```bash
bun -e 'process.stdout.write(require("node:crypto").randomBytes(32).toString("base64url") + "\n")'
```

Первый запишите в `X_CONNECTOR_CLIENT_SECRET`, второй в `X_CONNECTOR_ENCRYPTION_KEY`. Не меняйте ключ шифрования при обычном перезапуске: без прежнего ключа сохранённые подключения прочитать нельзя. Храните резервную копию ключа отдельно от зашифрованного файла. Файл `.env` и каталог `.liquid/` исключены из Git.

Запуск:

```bash
bun run connector:x
```

По умолчанию сервер слушает `127.0.0.1:8787`. На HTTPS reverse proxy направьте весь домен на этот порт, сохраняя исходный заголовок `Host`. Например, для уже установленного Caddy:

```caddyfile
x-connector.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

Проверка через публичный домен:

```bash
curl https://ВАШ-ДОМЕН/healthz
curl https://ВАШ-ДОМЕН/.well-known/oauth-authorization-server
curl -i https://ВАШ-ДОМЕН/mcp
```

Первые два запроса должны вернуть 200. Последний возвращает 401 и `WWW-Authenticate` с адресом OAuth metadata до подключения аккаунта. Настройте reverse proxy так, чтобы он не записывал query-параметры OAuth callback и заголовки `Authorization`/`Cookie` в access log.

## 3. Подключение в ChatGPT

Откройте **Plugins**, нажмите **+**, затем **Add custom MCP server**. Если в вашей версии интерфейса этот пункт находится в настройках приложений или коннекторов, используйте создание пользовательского MCP-сервера.

Укажите адрес:

```text
https://ВАШ-ДОМЕН/mcp
```

Выберите **OAuth** и задайте реквизиты коннектора:

| Поле ChatGPT | Значение из `.env` |
|---|---|
| Client ID | `X_CONNECTOR_CLIENT_ID`, по умолчанию `chatgpt-x` |
| Client Secret | `X_CONNECTOR_CLIENT_SECRET` |

Скопируйте точный redirect URI, показанный ChatGPT, в `X_CONNECTOR_REDIRECT_URI`. Сервер объявляет поддержку issuer identification, поэтому текущий документированный адрес: `https://chatgpt.com/connector_platform_oauth_redirect`. Если ChatGPT показывает другой адрес, используйте показанный. После изменения перезапустите сервер.

Сохраните коннектор, подключите его и подтвердите разрешения на странице X. Затем выберите его в новом чате через `@` и попробуйте:

```text
Найди последние посты от OpenAI про Codex и кратко перескажи со ссылками.
Прочитай https://x.com/ИМЯ/status/ID и объясни основной тезис.
Найди посты по запросу from:OpenAI lang:en -is:retweet.
```

Используются инструменты `search(query)` и `fetch(id)`. Оба возвращают structured content, текстовую копию результата и URL для цитирования. Обновление просроченного токена выполняется через стандартный OAuth refresh. При изменении инструментов обновите metadata коннектора в ChatGPT.

## Хранение и ограничения

- Authorization Code + PKCE S256 применяется на обоих этапах: ChatGPT → коннектор и коннектор → X. Callback связан с браузером через HttpOnly cookie. URI перенаправления и ресурс MCP проверяются точно.
- Поддерживается один заранее настроенный OAuth-клиент ChatGPT. DCR и произвольные сторонние OAuth-клиенты не включены. Разные подключения получают отдельные токены X.
- Токены X зашифрованы AES-256-GCM. Собственные access/refresh tokens хранятся как SHA-256. Файл обновляется атомарной заменой с правами 0600.
- Используйте один процесс на один файл хранилища. Для нескольких реплик нужна транзакционная база. Одновременно хранится до 1000 подключений, 1000 незавершённых входов и 1000 кодов.
- Незавершённый вход действует 10 минут, одноразовый код действует 60 секунд, неактивное подключение истекает через 30 дней. Refresh token коннектора ротируется при каждом обновлении.
- `/revoke` отзывает подключение на стороне коннектора. Полностью отозвать разрешения приложения X можно в настройках подключённых приложений X.
- Поиск ограничен 10 результатами, без автоматической пагинации. `fetch` читает один пост, включая полный текст длинного поста, если X возвращает `note_tweet`; тред целиком и медиафайлы не скачиваются.
- 401 от X требует повторного подключения аккаунта; 402/403 требует проверки API-доступа; 429 означает квоту X. Повторы платных запросов автоматически не запускаются.

## Проверки

```bash
bun test tests/integration/x-connector.test.ts tests/unit/x-connector-security.test.ts
```

Проверки поднимают настоящий HTTP MCP-сервер и используют официальный MCP SDK как клиент. Внешние OAuth и X API подменены локальной фикстурой: проверяются обе PKCE-цепочки, одноразовые коды, обновление и отзыв токенов, раздельные аккаунты, зашифрованное хранение, поиск и чтение. Реальный вход X и подключение из ChatGPT требуют настроенного приложения, домена и завершения входа пользователем.
