# Контракты выполнения после аудита Physicss

Изменения от 16 ноября 2026 устраняют потерю состояния и лишние обращения к модели. Проверки используют локальные протокольные fixtures, настоящий runtime и скрытый Electron. Они не подтверждают исправность внешнего relay, исторического бинарника или облачного образа.

## Поток провайдера

OpenAI Chat проверяет chunks, terminal и переданный finish reason. После явного `[DONE]` отсутствие `finish_reason` допускается: текст завершает ответ, а полные проверенные tool calls продолжают цикл инструментов. Поток без `[DONE]` остаётся обрывом. Повреждённый JSON, неизвестный payload, пустой результат и неполный tool call имеют разные причины ошибки. Незавершённый JSON аргументов не превращается в исполняемый вызов. `length` сохраняет значение `max_tokens`.

`provider.response` хранит безопасный receipt: протокол, request identity, исходную причину завершения, счётчики разбора, наличие usage и длительность. Операционные diagnostics сохраняют retry metadata и вложенный lifecycle. Текст модели, ключи и prompts в receipt не включаются. Исторические 15 пустых ответов нельзя объяснить окончательно без исходных ответов провайдера.

Реестр добавляет к receipt идентификатор попытки и фактические provider/model до failover. Usage не получает цену выигравшего резервного маршрута. Локальный отказ из уже известного quota cooldown имеет `requested: false`. HTTP retries внутри одной попытки пока объединены в один receipt: `missingRequests` считает попытки без usage, а не все отдельные сетевые обращения.

`model_quota_exhausted` имеет отдельный класс model quota. Несколько handle одного provider/model используют общий cooldown. Явное `models.<id>.quotaGroup` объединяет aliases с общей квотой; другая группа остаётся доступной. Группы задаются по контракту провайдера, а не выводятся из названий моделей. Изменение авторизации очищает старое quota state.

## Рабочий контекст и результат

API window остаётся техническим пределом. У Talker рабочий набор 32000 токенов, у Worker 96000; резерв и размер system/tools учитываются отдельно. Talker по умолчанию использует reasoning `none`, его явно настроенный режим сохраняется.

Рутинные tool events отображаются напрямую. Ошибка Worker не запускает Talker для объяснения ошибки. Успешный результат поступает в приёмку и затем в один содержательный ответ.

`context complete` принимает точные findings, risks, result и finalResult. Полный отчёт и transcript архивируются до замены истории. Готовый finalResult завершается атомарно после проверки критериев. Структурированный checkpoint обходится без дополнительного модельного суммаризатора. Чтение evidence и архива допустимо при восстановлении без фиктивной рабочей страницы.

Задание содержит текущий шаг, вопросы, границы источников, ожидаемые outputs и критерии достаточности. Исходная речь пользователя хранится отдельно дословно. Только наблюдаемый успешный tool result может подтвердить критерий, которому назначен такой тип evidence.

## Расходы чата

Один task ledger принадлежит всему чату, включая продолжения и перезапуски. Основные запросы, Talker, Worker, субагенты, оформление отчёта, Twin, vision, перевод и compaction учитываются в общей сумме. У каждого прогона остаётся собственный таймер.

`usage` означает полученный receipt. `usage.unavailable` означает отсутствие receipt, включая неудачный запрос. Неполная стоимость не показывается как ноль. Известная часть стоимости остаётся нижней границей и может исчерпать настроенный лимит. Неизвестный фактический расход не позволяет гарантировать точный денежный потолок.

Durable `task.budget` записывается после изменения ledger. Usage после последнего snapshot воспроизводится один раз. Историческая цена без сохранённого billing receipt может отличаться от актуальной конфигурации.

Twin сохраняет отдельные charges фактических маршрутов и число попыток без receipt, поэтому успешный fallback не скрывает неопределённость предыдущего запроса. Оформление отчёта субагента использует тот же учёт маршрутов. Локальный quota reject не добавляет неизвестную стоимость; live и replay дают одинаковые суммы.

## Файлы, права и удалённые операции

Scratch расположен в `.flecten-scratch/<sessionId>`, переживает отдельный shell call и передаётся через TMPDIR. Курсор чтения длинной строки продвигается по символам и учитывает UTF-8. Обзор корня и пагинация glob позволяют получить карту проекта без обязательного обхода assets и caches.

Session grants сохраняют владельца, точную область и fingerprint политики. Replay не превращает их в глобальные разрешения и не отменяет новое явное deny.

Remote jobs используют стабильный handle, сохраняемый перед submit. Detached runner хранит PID/start identity, stdout/stderr и атомарный exit record. Потеря SSH-ответа означает неопределённую операцию, проверяемую через status того же handle. Повторный submit с тем же id и argv идемпотентен.

SSH capability проверяет живой agent и доверенный host key. В sandbox передаются нужный socket и отдельный public known-hosts file; приватные ключи и всё дерево `.ssh` не открываются. Remote command остаётся непрозрачным для анализа локальных путей.

Успех shell означает exit status команды. `expectedOutputs` дополнительно проверяет файлы, размер и при необходимости SHA-256. Проверенный артефакт и exit 0 представлены раздельно.

## Проверки

Контрактные регрессии находятся в `tests/unit/chat-stream-contract.test.ts`, `page-deliverables.test.ts`, `harness-tool-contracts.test.ts`, `ssh-capability.test.ts`, `remote-jobs.test.ts` и `tests/integration/task-accounting.test.ts`. `tests/e2e/task-accounting.spec.ts` проверяет отображение неизвестного расхода на 1480x940 и 1180x640.

`tests/integration/provider-accounting.test.ts` проверяет расходы failover через настоящий локальный HTTP transport. `tests/integration/mcp-discovery-service.test.ts` проходит реальный AppService, HTTP MCP, activation, смену модели, replay и compaction. До активации модель получает каталог MCP имён и описаний; полные схемы выбранных инструментов появляются после `tool_catalog activate` и сохраняются в контексте чата.

В Physicss dataset manifest и `3d/REPRODUCIBILITY.md` связывают source frames, masks, COLMAP views и runtime. Исторические rembg weights/version, immutable cloud image и отсутствующий исходник внешнего 2DGS build остаются внешними ограничениями воспроизводимости.
