# Flecten: Making Depth Approachable

November 17, 2026. Research backing the [desktop design standard](../design.md), documenting design rationale and migration order while separating target direction from current implementation state.

## Selection Criteria

We evaluated products that require zero onboarding up front while rewarding mastery over time. Visual polish alone was insufficient; every reference was evaluated against three questions: what is legible before interaction, what reveals itself strictly on demand, and how the interface returns users to a familiar anchor.

Nine Exa research passes covered Things, Arc, Craft, Flighty, Apple Photos, Raycast, Linear, accessibility standards, and expressive consumer software, followed by close readings of 18 primary sources. Secondary checks across IDEs and pro creative tools calibrated terminology, though their chrome density and visual style were intentionally excluded as models. Conclusions below draw from product documentation, creator teardowns, and Apple platform guidance rather than first-party usability testing of those apps.

## What Transfers to Flecten

| Reference | Observation | Concrete Application in Flecten |
| --- | --- | --- |
| [Things: task design](https://culturedcode.com/things/features/) and [Magic Plus](https://culturedcode.com/things/support/articles/2803582/) | Tasks expand inline where found, revealing metadata on demand; Magic Plus pairs a standard click with power-user drag placement. | Activity rows expand in place so collapsing returns to the exact same row; message editing reuses the primary composer; standard click and keyboard paths remain self-sufficient. |
| [Arc: Spaces & tab organization](https://start.arc.net/cure-tab-overload), [Command Bar](https://start.arc.net/command-bar-actions) | Sidebar establishes workspace context while frequent actions share a fast entry point. | Projects and tasks orient the user while History, Changes, and Terminal remain views of the active task. Shortcuts accelerate visible controls without implying auto-archiving or a separate command palette. |
| [Flighty: creator teardown](https://developer.apple.com/news/?id=970ncww4) and [live flight status](https://flighty.com/help/live-activities-widgets) | Time-critical delta state (gate, delay reason, ETA) sits front and center so users rarely need raw logs. | Surface the current human-readable action or blocking question first, including known wait/block reasons; keep elapsed time and step counts secondary, and never invent progress percentages unknown to the runtime. |
| [Craft: blocks & pages](https://support.craft.do/en/write-and-edit/blocks-and-pages) and [navigation](https://support.craft.do/en/introduction/navigation) | Content dictates layout rhythm, letting readers drill into nested details without turning every paragraph into a separate screen. | Render responses with editorial hierarchy: prose, inline previews, code, and media take natural proportions along a single reading axis rather than uniform event-feed cards. |
| [Apple Photos: single-asset view](https://support.apple.com/guide/photos/view-photos-and-videos-pht8b9ba4aa9/mac) | A single item expands from the grid to claim the canvas while keeping primary actions anchored and metadata optional. | Open file changes in a full diff view rather than a cramped widget. At 1180x640, give the active view full width; allow side-by-side split only when both panes have room to breathe. |
| [Raycast: search bar](https://manual.raycast.com/search-bar) and [Action Panel](https://manual.raycast.com/action-panel) | The default action is obvious before opening any menu; secondary actions scope strictly to the selected target. | Keep the primary composer action unambiguous. Reveal `Queue` and `Steer` only when a non-empty draft meets an active run; scope file and task menus locally without inventing extra send modes. |
| [Linear: reducing visual noise](https://linear.app/now/behind-the-latest-design-refresh) | Chrome recedes once a workspace is chosen so content dominates visual weight. | Pair a deeper graphite frame with a slightly lighter reading canvas while keeping navigation labels high-contrast. Do not copy Linear's palette, list density, or overall aesthetic. |
| [!Boring: design philosophy](https://notbor.ing/words/here-we-go) and [Habits teardown](https://developer.apple.com/news/?id=9ab1g4r3) | Signature personality lives in specific state transitions and tactile moments while core controls stay predictable alongside custom 3D scenes. | Concentrate motion in mode switches, the live indicator, and the dedicated Twin stage to reinforce state changes; keep text inputs, menus, keyboard navigation, and errors crisp and conventional. |
| [Apple HIG: Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility.md) and [WCAG 2.2](https://www.w3.org/TR/WCAG22/) | Familiar patterns lower cognitive load, meaning requires multiple cues beyond color, and focus rings must never hide behind sticky chrome. | Verify static frames and keyboard traversal first. Carry meaning with shape and copy before accent color, and never excuse low contrast on secondary labels via opacity. |

## What Conflicted in the Previous Spec

| Issue | Impact | Resolution |
| --- | --- | --- |
| New sections specified brisk interruptible transitions while legacy sections kept 460 ms button transitions, 760 ms bouncy disclosures, and word cascades. | Following legacy timings caused text jitter and sluggish controls. | Consolidated into a single state-transition table aligned with [motion.ts](../ui/src/lib/motion.ts) (`140`/`190`/`240` ms and `220`/`160` ms); removed legacy recipes. |
| Blanket caps on line counts, accents, and control heights (`40 px` conflicting with `32`/`28 px` desktop controls). | Treated transient popovers, live dots, focus rings, and structural seams as interchangeable noise. | Govern hierarchy by visual weight and role: distinct rules for layout seams, focus rings, and interactive hit targets (`32`/`28 px` desktop, `44 px` coarse pointer). |
| Assumed a permanent three-column layout even though [workspace.svelte.ts](../ui/src/lib/workspace.svelte.ts) and [App.svelte](../ui/src/App.svelte) default to a single view and gate split width dynamically. | Cramped both prose and diffs simultaneously on narrower viewports. | Anchor layout rules to available workspace width: single view by default, persistent opt-in split that collapses cleanly below threshold and restores when space returns. |
| Framed ambient live WebGL as a workspace-wide template while omitting the Twin stage from visual hierarchy rules. | Encouraged redundant glow effects next to already-legible status indicators. | Isolate Twin within its own meaningful stage; prioritize readable status marks and copy for live runs, halt hidden renders, and forbid competing shaders. |
| Heavy focus on micro-feel tuning with sparse guidance on first-five-second comprehension. | Allowed visually polished screens whose workflow remained opaque to new users. | Lead with a single clear entry point, plain-language activity rows, and direct links to evidence, keeping technical payloads behind stable disclosures. |

Baseline checks compared tokens, UI states, and the repository's [desktop screenshot](assets/desktop.png) (capturing the prior implementation rather than the target spec). The iris desktop accent is defined in [app.css](../ui/src/app.css), while the copper-accented marketing site follows [web/design.md](../web/design.md).

## Rollout Order

1. **End-to-end dialogue pass.** New chat -> prompt -> active run -> response with verifiable evidence. In [Thread.svelte](../ui/src/components/Thread.svelte), [RunGroup.svelte](../ui/src/components/RunGroup.svelte), and the composer, align the shared reading axis and separate human-readable actions from raw technical payloads. Introduce the signature gesture here: the left status mark stays anchored and extends a short vertical edge across only that run's expanded rows, without adding new event logs or intermediate state layers.
2. **Verifiable outcomes.** Style existing file-change and check references calmly and distinctly. Verify round-trip navigation from thread links into real diffs and back to the exact scroll offset, documenting any missing data links explicitly before UI work.
3. **Extend the grammar across remaining surfaces.** Apply the `anchor -> primary object -> action` hierarchy to IDE, Settings, and Twin without cloning thread visuals. Preserve control geometry across state changes and verify identical scenarios at 1480x940 and 1180x640 with keyboard navigation and `prefers-reduced-motion`.

Explicitly rejected directions: terminal-emulator aesthetics across the whole app, equal-weight dashboard tile grids, novelty navigation chrome, permanent background blur, and brand-coined labels for standard actions. Expressiveness passes when an empty screen makes the first step obvious and a busy screen retains its character in a static screenshot.
