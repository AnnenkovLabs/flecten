## Підготовка

Потрібні Bun 1.4 і Node 20 або новіші. Node потрібен лише для Electron.

```bash
bun install
bun run dev help
bun run app:dev
```

## Перед PR

Запусти всі перевірки:

```bash
bun test
bun run check
bun run lint
bun run build:ui
```

Якщо змінював вікно, додай знімок або опиши перевірку в браузері на 1480x940 і 1180x640. Перевір стани: порожній, завантаження, зупинка, reduced motion.

## Правила коду

- Один файл відповідає за одну річ. М'яка межа 300 рядків, жорстка 500.
- `core` не імпортує `ui`, `shell` і `store`.
- Інтерфейс не читає файли й не викликає моделі.
- Дані з моделі, файлів і web перевіряються схемою на межі.
- Ядро не пише в `console`. Події йдуть через шину.
- Промпти лежать у `prompts/`, а не в коді.
- Секрети вирізаються до запису в лог.
- Коментар пояснює причину, а не дію.
- Тимчасове спрощення позначається `ponytail:` з межею та шляхом розвитку.

## Інтерфейс

- Читай `design.md` перед зміною візуальної поведінки.
- Компоненти лежать в `ui/src/components`, стан і чисті функції в `ui/src/lib`.
- Демо-дані змінюються лише в `ui/src/lib/demo.ts`. Компонент не зберігає копію цих даних.
- Токени, шрифти й базові стилі лежать в `ui/src/app.css`. Не додавай другий набір токенів.
- Новий компонент отримує дані через props. Прямий імпорт `demo.ts` допустимий лише в контейнерах екрана.
- Інтерактивні елементи працюють з клавіатури й мають `aria-label` або видимий підпис.
- Анімація не потрібна для розуміння стану. `prefers-reduced-motion` має лишати статичний кадр.

## Залежності

Нова залежність потребує запису в `docs/DECISIONS.md`: контекст, рішення, наслідки. Спершу перевір стандартну бібліотеку Bun, потім пакет.

## Коміти

Один коміт це одна зміна змісту. Повідомлення в наказовому способі: `add spec parsing`, `fix page boundary`. Секрети й `.liquid/` не комітяться.

## Поведінка

Обговорюй код і рішення, не людей. Образи, цькування та публікація чужих даних неприпустимі. Про проблему повідом власнику репозиторію приватно. Див. [Кодекс поведінки](../../CODE_OF_CONDUCT.md).
