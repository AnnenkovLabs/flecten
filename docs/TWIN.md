# Twin

Twin acts as a literal clone of the user (`src/app/session-twin.ts`). Backed by a dedicated persona profile, Twin learns first via button-triggered source imports and continuously on the fly (Taste-style) from every user message, reaction, and frustration during live work. Running quietly in the background with base read-only tools (`read`, `grep`, `glob`, and `inspect_messages` in `src/twin/tools.ts`), Twin watches agent progress, barges into the chat mid-work when agents take a wrong direction, and audits final agent summaries, posting user-like messages (`actor: "twin"`) directly into the active chat thread wrapped in a 3D furry rounded-rectangle GLSL shader (`TwinBlob.svelte`).

## Execution Loop

1. When the user sends a prompt or steers an active run, Twin observes the reaction and preceding assistant context in the background (`twin.observe`), extracting durable preferences and frustrations into the persona without interrupting the chat.
2. During execution, Twin monitors completed tool steps in the background without exposing its own internal tool calls or thinking steps to the user. At mid-work checkpoints, Twin can use `read`, `grep`, and `glob` to inspect project state and barge in with a `revise` steer message (`actor: "twin"`) directly in the chat thread (and to Worker when active).
3. Worker `ask` questions route to Twin first so Twin can pick the best-supported option; real security and filesystem approvals remain strictly in `PermissionEngine`.
4. Once an agent run finishes and posts its summary, Twin audits the summary and evidence against the user's request and taste. Returning `revise` sends a new user-role run (`actor: "twin"`) in the same chat thread in the user's first-person voice so agents immediately fix what they got wrong.
5. A failed Twin review call never counts as approval, new human input invalidates in-flight verdicts, and user stop cancels active Twin reviews.

The UI renders Twin's chat messages inside a 3D raymarched rounded-rectangle GLSL blob with volumetric fur along its contour (`ui/src/components/twin/TwinBlob.svelte`, `ui/src/lib/twin/blob-renderer.ts`, `ui/src/lib/twin/twin-blob.frag`), while the Twin drawer exposes learned traits, cited evidence, and token spend. Anger states represent typed reactions to task quality rather than claims about the user's real-world mood, and Twin preserves the tone and directness evidenced in imported transcripts.

## Source Filtering, Agentic Training, and Character Controls

The Twin view mirrors the trailer layout: interactive 3D character, discovered transcript and memory sources with live session counts, training model/reasoning/variant selector, cost notice, training flow with subtle expandable agent trace, and trait editor. The character renders in real time via the v12 WebGL2 raymarched SDF shader (volumetric body, fur, eyes, paws, updated violet palette, and extended anger facial/body rig, with zero external mesh assets).

Supported transcript and memory importers (`src/twin/`): **Claude Code** (sessions + `~/.claude/projects/*/memory` and `CLAUDE.md`), **Codex** (`.jsonl` and `.jsonl.zst` sessions + `~/.codex/memories` and `AGENTS.md`), **Cursor** (structured exports + `.cursor/rules`), **OMP** (sessions + `mnemopi.db` memories and `AGENTS.md`), **Kilo** (CLI/Desktop `kilo.db` SQLite, IDE task folders, and `AGENTS.md`/memory), **DeepSeek** (`.jsonl`/`.jsonl.zst`/`.jsonl.zstd` sessions + `~/.dsh/memories`), **OpenCode** (read-only SQLite v1/v2 + `instruction_entry`), **Hermes** (read-only SQLite + `~/.hermes/memories`), **Command Code** (sessions + full global and project `.commandcode/taste` category hierarchy), and **Flecten** (sessions + `.flecten/memory.json`). Discovery and ingestion strictly filter out service sessions, internal prompts, and subagents across all harnesses (such as Claude `subagents/` directories, `isSidechain`, `agentId`, and `sourceToolAssistantUUID` records; Codex `thread_source: "subagent"`, `parent_thread_id`, and non-user provenance blocks; OMP `parentSession` and nested subagent folders; Command Code `isMeta`, `isSidechain`, `isAutomated`, `agentId`, and non-user sources; OpenCode `parent_id` child sessions; Hermes `parent_session_id`, `subagent` sources, and `display_kind` delegation notices; and Flecten `_worker` sessions, `internal` runs, and Twin's own `actor: "twin"` messages).

During training, Twin processes all unread user messages and saved memories in batches without artificial session/message/character ceilings. For each batch, it receives recent reactions, a structured index of remaining items with file references, and base read-only tools (`inspect_messages`, `read`, `grep`, `glob`) scoped to the project and selected source directories.

Starting training expands the portrait into the full stage over `500 ms`. Redacted message preview cards (up to 16 real excerpts per import, <= 4,000 characters each, kept strictly ephemeral in memory) arc continuously into Twin along overlapping trajectories: each absorption steers gaze and paws, impulses the spring rig, and ripples across the surface without resetting velocity, settling to `100%` and a ready reaction once the backend reaches `ready`. Pause and `prefers-reduced-motion` freeze both cards and character; cancelling returns immediately to source selection.

Users can drag to rotate Twin, move the cursor to steer gaze, click or press `Enter`/`Space` to greet, use arrow keys to rotate/look, and press `Home` to reset framing. The header toggle remains reachable mid-training: switching Twin off plays an `8s` farewell sequence (`6.5s` tearful reach, `~1s` gravity-accelerated topple as the supporting paw slips, normal-axis squash on impact, delayed crest/paw follow-through, and desaturation to gray over `2.4s`, persisted in `twin.json` so restarts render the resting gray pose directly), while toggling back on interrupts the fall and lifts Twin back up in color with hearts over `3.2s`. Disabling cancels active training while keeping already saved traits.

Rendering pauses off-screen and in hidden windows; thumbnails draw static poses, internal resolution scales with load up to `512 px` at max `1.5` DPR and `24 fps`, WebGL resources release on unmount, and a static WebP fallback covers pre-first-frame or lost-context states. Interacting with the 3D character makes zero model calls.

Newly learned traits activate Twin automatically on completion and support CAS editing/deletion (`expectedRevision`), plus zero-model manual lessons from IDE code diffs (`twin.teach`). Twin can also be enabled manually prior to training to enforce literal prompt intent without fabricated traits. All Twin model calls (`train`, Worker reviews) accept a single JSON object (raw or inside one CommonMark code fence) validated by Zod and exact quote matching, recording spend even when malformed responses are rejected and publishing to memory only after atomic disk commit.

## Storage, Budgets, and Protocol

- **Persistence**: `.flecten/twin.json` (schema v2, atomic writes, fully separate from `.flecten/memory.json`).
- **Batching & storage bounds**: training chunks unread items into ~120-message / 80,000-char batches; store holds up to 200 active traits and 50,000 processed message hashes (skipping unchanged messages on re-import).
- **Runtime context caps**: latest 16 human messages (<= 10,000 chars), latest 12 tool results (<= 12,000 chars), and most recently updated traits up to ~18,000 chars (no semantic embeddings or full-repo snapshots).
- **Visual inspection**: up to 2 recent Worker tool images (<= 2 MiB each) passed as native multimodal media from verified session attachments (never base64-in-text; skipped with an explicit prompt note on text-only models; Twin never launches browsers or takes screenshots itself).
- **Accounting & RPC**: Twin calls and Worker revision rounds roll up into the shared chat budget ledger (training tracked separately) via `twin.get`, `scan`, `train`, `cancel`, `configure`, `review`, `update`, `forget`, `teach`, and durable `twin.activity` events.

"Training" updates a structured persona document rather than fine-tuning model weights; automated suites verify routing, cancellation, and bounded revision loops rather than guaranteeing subjective human agreement on open-ended tasks.
