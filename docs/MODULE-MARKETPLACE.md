# Маркетплейс модулей

**Settings → Modules → Marketplace** показывает встроенные пакеты и явно подключённые каталоги. Установка проходит через действующий module package reader. Модель не запрашивается, новый код до подтверждения доверия не выполняется.

## Встроенные пакеты и каталог репозитория

Исходники пакетов лежат в `src/marketplace/modules/`. Публикуемый каталог образуют `src/marketplace/index.json` и base64-пакеты в `src/marketplace/packages/`: `bun run build:marketplace` читает каждый пакет через `readModule`, кодирует файлы и записывает индекс с SHA-256 и ссылками на `raw.githubusercontent.com`. Каталог коммитится вместе с исходниками; интеграционный тест сверяет revision и байты пакетов с исходниками, поэтому забытая перегенерация падает на проверке.

Источник `bundled` сначала запрашивает каталог репозитория по HTTPS с таймаутом 5 секунд. Пока репозиторий приватный или сети нет, запрос не удаётся, и маркетплейс переходит на локальные файлы: `dist/module-marketplace` рядом с бинарём (копирует `build:agent`, Electron включает папку в resources) или `src/marketplace/modules/` в разработке. Когда репозиторий становится публичным, индекс и пакеты начинают браться с GitHub без обновления приложения. Описание, версия, зависимости, capabilities и SHA-256 читаются из настоящих файлов. Каталог доступен без сети.

## Внешний каталог

В **Catalog sources** укажите URL JSON-каталога и нажмите **Add catalog**. Разрешён HTTPS без credentials и fragment. URL сохраняется в `modules.marketplaces` конфигурации проекта, максимум восемь источников. Перед сохранением проверяется весь каталог. Ошибка источника показывается отдельно; **Refresh marketplace** повторяет загрузку.

```json
{
  "schemaVersion": 1,
  "name": "Example modules",
  "modules": [
    {
      "title": "Project guide",
      "publisher": "Example team",
      "category": "workflow",
      "manifest": {
        "schemaVersion": 1,
        "name": "project-guide",
        "version": "1.0.0",
        "description": "Project guidance loaded on demand",
        "instructions": ["instructions.md"]
      },
      "revision": "<SHA-256 returned by readModule>",
      "packageUrl": "https://example.org/project-guide-1.0.0.json"
    }
  ]
}
```

`category` принимает `workflow`, `interface` или `platform`. `manifest` проверяется стандартной схемой пакета. Имена модулей внутри каталога уникальны. Одинаковые имена разных издателей остаются разными предложениями, но в проект устанавливается только один пакет с данным именем.

## Публикация пакета

Пакет по `packageUrl` содержит исходные файлы в base64. Относительные пути совпадают с путями в папке модуля:

```json
{
  "schemaVersion": 1,
  "files": {
    ".flecten-module/module.json": "<base64 of the manifest file>",
    "instructions.md": "<base64 of instructions>"
  }
}
```

Пакеты Flecten публикуются командой `bun run build:marketplace`: после изменения исходников перегенерируйте каталог и закоммитьте его вместе с ними. При публикации стороннего пакета из корня репозитория используйте `readModule` из `src/modules/package.ts`. Он возвращает `manifest`, `revision` и `files`. Кодирование каждого значения через `Buffer.from(bytes).toString("base64")` даёт содержимое `files` для загрузки на HTTPS-хостинг. В catalog entry поместите возвращённые `manifest` и `revision`; произвольный хеш архива не подходит. Меняйте версию и revision вместе с файлами. Публикация не требует изменения приложения.

Загрузка ограничена 15 секундами на запрос, 2 МиБ для каталога и 45 МиБ для JSON-пакета; redirects запрещены. После декодирования действуют пределы module reader: 32 МиБ и 5000 entries, без symlink, специальных файлов и выхода за каталог. SHA-256 всех путей и байтов должен совпасть с просмотренной записью, manifest также сравнивается целиком. Несовпадение прерывает установку до публикации.

## Зависимости и доверие

`requires` разрешается по явному графу в выбранном каталоге. Уже установленные зависимости сохраняются. Цикл или отсутствующий пакет дают ошибку до записи. Одна установка ограничена 32 пакетами и 128 МиБ. Сначала читаются и проверяются все пакеты, затем они устанавливаются. Если запись или сохранение конфигурации не удаётся, новые папки удаляются. Существующие пакеты не перезаписываются.

Каждый новый пакет остаётся недоверенным и выключенным до **Trust this version** на вкладке **Installed**. Интерфейс модуля требует отдельного **Use module interface**. Обновления не применяются автоматически: установленные пакеты управляются существующим lifecycle, а новая установка с тем же именем отклоняется. SHA-256 проверяет целостность выбранных байтов, авторство стороннего издателя определяется самим источником каталога.

## Контракт приложения

`modules.marketplace` принимает `action: list | install | addSource | removeSource`. Для install передаются `source`, `name` и просмотренный `revision`; ответ содержит `moduleMarketplace` и `moduleState`. Схемы лежат в `shared/module-marketplace.ts`, данные экрана в `ui/src/lib/settings/modules.svelte.ts`. Компоненты получают store через props, файловая система и сеть доступны только sidecar.

`tests/integration/module-marketplace.test.ts` проверяет protocol, зависимости, trust, активацию настоящим агентом, целостность, пути и отказ источника. `tests/e2e/module-marketplace.spec.ts` проверяет поиск, категории, установку и доверие в скрытом Electron, включая снимки на 1480×940 и 1180×640.
