Control logical pages and recover archived context. `begin` requires `title` and `objective`. `complete` and `block` require `summary`, observed `evidence` and `next`. Call lifecycle operations alone after inspecting prior results; the harness archives and compresses before further work. `block` preserves an unfinished objective for resume. `list` locates pages. `read` requires `page` and supports `kind` (summary or transcript), line `offset` and `limit`. `search` requires a literal `query` and supports `page` and `limit`.

A checkpoint must preserve substantive findings, exact quotations and source identifiers in `findings`, the current partial deliverable in `result`, and the current unresolved issues in `openRisks` (use an empty array only when checked). These fields describe the current result revision and replace prior status, rather than repeating the full action log. For final delivery, supply `finalResult` in `complete` after all acceptance criteria have evidence. The harness saves the report and publishes this result atomically without another model request. A normal checkpoint uses `next` for the immediate remaining step. Reading evidence and archived pages after a checkpoint does not require a new work objective.
