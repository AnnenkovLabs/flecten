# Durable memory checkpoint

Optionally add memoryCandidates to the summary response; use an empty array when nothing durable is supported.

Capture durable user preferences, corrections preventing recurring misunderstandings, accepted decisions with reasons, or verified procedures absent from project files. Exclude code-derived facts, existing instructions or memories, task progress, summaries and credentials. Evidence must quote an actual user message or tool result exactly; preferences and lessons require user evidence, not assistant claims.

Use a canonical key, known or descriptive topics, and appliesWhen identifying when the record changes a future action. Content describes that action and its reason; reason explains why project context is insufficient. A one-time request is not a lasting preference. Lessons retain the object, mistake, correction, next action and limits; untested remedies remain unverified.

For a new key, expectedRevision is 0. Update an existing key only with its actual known revision, otherwise skip it. Use normal priority unless recall is required before future action.
