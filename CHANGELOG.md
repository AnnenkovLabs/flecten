# Изменения

## Не выпущено

- Продукт переименован в Flecten: интерфейс, промпт, документация, пакет, бинарник `flecten-agent` и установщики. Новый конфиг `flecten.config.json` и переменные `FLECTEN_*` имеют приоритет; старые конфиги, ключи, ссылки и профиль остаются совместимыми.
- Медный акцент заменён на ирисовый во всём интерфейсе, HTML-ответах, живом свечении и иконках приложения. Тёмный графит и анимации сохранены.

- Grep fallback выполняет пользовательский pattern в прерываемом worker; glob/grep учитывают вложенные `.gitignore` и правила родительских папок. `read` хранит только bounded excerpt даже для строки в64МиБ.
- Shell checkpoint deadline включает очередь mutex и сохранение объектов; при истечении бюджета поздний manifest не появляется. Linux stop находит потомков с `setsid` даже после выхода родителя; macOS process/RSS/socket metrics используют `ps` и `lsof`.
- Windows resource monitor получает process/RSS/TCP/UDP через CIM и останавливает инструмент при ошибке запроса. Foreground/background используют настроенный shell, Windows default выбирает `cmd.exe` с native env. Persistent Windows PTY использует штатный ConPTY Bun 1.4.2; AppContainer, отдельный Job Object для каждой команды и native платформенная приёмка остаются открытыми.
- Sidecar включает штатный Bun `no-orphans`: принудительное завершение Electron не оставляет агентские процессы. Терминал использует протокол реальной оболочки сессии, ждёт полный frame с exit code через границы chunks; ошибка запуска не регистрирует неработающий терминал.
- Ключи keychain разделены по каноническому проекту и привязаны к protocol/baseUrl/proxy. Старые ключи без установленного назначения требуют повторного ввода.
- Изменение плагина удаляет его MCP tools и hooks из работающих сессий до явного доверия новой версии. Субагент не может расширить permissions родителя или обойти allowed-tools активного skill.
- CI сохраняет text/LCOV coverage, запускает visual regression с обязательной проверкой среды, packaged smoke на Linux/macOS/Windows и reusable quality gate перед release. Tag должен совпадать с версией; публикация выбирает только release artifacts.
- Реальное локальное распознавание Vosk проверено через Electron microphone, MediaRecorder, sidecar и редактируемый composer. Изолированная установка движка не меняет пользовательские настройки.

- Lifecycle сессии, очередь, approvals и jobs приходят из канонического backend snapshot с epoch/revision; ошибка IPC не меняет подтверждённое состояние UI.
- Переносимый экспорт атомарно создаёт папку с журналом и независимыми копиями вложений.
- Обновления проверяют Ed25519 manifest и фактические SHA512/size installer; без встроенного ключа или подписи канал блокируется.
- Финальная приёмка исправила обновление каталога навыков после Save и потерю diff после повторной записи того же содержимого. Метаданные и частые действия доведены до 12px и 40px; пути IDE сохраняют имя файла.
- Coverage измеряет реальные rune-модули через Bun plugin без аварийного data URL loader; порог85% сохранён. Подробная карта проверок: `docs/ACCEPTANCE-2026-11-10.md`.

- Вложения переживают crash, compaction, очередь и fork: metadata в событиях, исходные bytes в закрытых артефактах с checksum.
- Длинные треды виртуализированы с поиском по полной истории, восстановлением позиции и следованием за ответом.
- Контекст модели переведён в Markdown с полными полями; PageWriter использует JSON Schema, trimming сохраняет границу недоверенных данных.
- Повторная авторизация провайдера обновляет токен в работающем адаптере и проверяет выбранную модель.

- MCP подключён к настройкам: health, reconnect, каталоги, логи, Streamable HTTP, OAuth discovery/PKCE/loopback и формы elicitation. Секреты остаются в sidecar.
- Плагины устанавливаются из папки, проверяются по SHA-256 содержимого и подключают skills, команды, роли субагентов, MCP и hooks. Изменение файлов снимает доверие.
- Skills: trust, версии, browser ресурсов, dedupe активаций, live reload и реальное allowed-tools в продуктовом registry с восстановлением после перезапуска.
- Все 11 событий hooks подключены к циклу и настройкам, доступны HTTP, async, fail-closed, тест сохранённого хука и лог.
- Structured @: выделение, символ, задача, публичный GitHub PR и MCP ресурс; сырое сообщение сохраняется буквально, очередь хранит прикреплённый контекст.
- Аудиовложения OpenAI Chat/Gemini, проверка возможностей протокола и модели, учёт размеров изображений и длительности WAV/MP3/FLAC.
- Настройки провайдера сохраняют черновик при обновлении моделей, проверяют связи context/output/reasoning, показывают источник ключа и требуют именованного подтверждения удаления.
- Полные stdout/stderr пишутся на диск с backpressure, excerpt в памяти ограничен. Потоковая redaction защищает секреты, разделённые между chunks.
- Экспорт JSONL истории из меню задачи, политика хранения и корзины в настройках. OS deep links выбирают сохранённую задачу без запуска прогона.
- DiagnosticsRuntime подключён к sidecar: structured logs, trace id, crash report, локальный bundle и отправка технических счётчиков только по согласию.

Автономная работа без страха: откат, бюджет, переживание падений.

- Откат shell-команд: `bash`, `terminal` и `git` снимают снимок до и после команды в теневом git `.liquid/shadow`, `/undo` откатывает их как правки файлов. Бюджет 5 с на команду, на 100 000 файлов снимок стоит от 270 до 530 мс. Destructive-команды спрашивают подтверждение с названием риска, `/undo` не трогает конфиг, `.env` и секреты без явного выбора.
- Фоновые задачи: `bash` с `background: true`, тул `jobs` (`list`, `read`, `wait`, `stop`), уведомление только задаче-владельцу, полоса задач над композером с остановкой. У `bash` есть длительность в результате, долгий тул прерывается из карточки вместе с деревом процессов.
- Настройки терминала: shell, env allowlist, scrollback, таймауты, ANSI и уведомления применяются без перезапуска.
- Несколько задач сразу: пул до `sessions.maxConcurrent` задач, подтверждение из любого окна попадает в спросившую задачу, Allow All и Deny All делят ids между задачами.
- Переживание падений: очередь на диске со стабильными id, продолжение прерванных прогонов после падения sidecar, журнал событий с `seq` и `events.replay` для перезагруженного окна.
- Бюджет прогона: токены, стоимость и wall-clock с потраченным и остатком в окне.
- Недоверенные данные: вывод файлов, web и MCP приходит модели в Markdown-разделе `Untrusted data` с источником, служебная строка отдельно, в карточке ссылка на полный лог.
- Системный промпт: общий бюджет 24 000 токенов с точным счётом, версия и хеш в `session.started`, миграция конфига на `schemaVersion: 2`.
- Одно окно на профиль и одно ядро на проект: второй запуск фокусирует первое окно, размер и положение окна восстанавливаются, `.liquid/sidecar.lock` не даёт двум ядрам писать одну сессию (`project_locked`). Заголовок окна называет открытую задачу.
- Уведомления: стопка над композером, ошибки видны 6 секунд и остаются в карточке прогона, наведение и фокус ставят expiry на паузу.
- Блоки кода с языком и копированием, диаграммы Mermaid с подписями и текстовой альтернативой, HTML-саммари на токенах harness с медью только в разрешённых ролях.
- Атомарная запись конфига, секретов (0600), очереди и кэшей; конфиг пишется туда, откуда прочитан, даже через симлинк.
- Docs as code: `docs-check` сверяет PROTOCOL, TOOLS, конфиг и security с кодом в обе стороны; порог покрытия 85% строк с текстовым отчётом и LCOV в CI; визуальная регрессия на 1480x940 и 1180x640.
- Исправлено: `/undo` не находил чекпоинт из-за формы `checkpoint.list`, правка сообщения в очереди теряла id, бюджет промпта 8 000 обрезал AGENTS.md, ответ на подтверждение задачи не в фокусе терялся, уведомление о фоновой задаче приходило в чужую задачу, «Удалить 1 моделей», черновик провайдера терял варианты, фокус композера пропадал после первой отправки, Mermaid рисовал пустые прямоугольники.
- Просмотр файла в окне: «Открыть файл» в карточках `read`, `write`, `edit`, в заголовке diff и «Полный лог» у тула открывают встроенный просмотрщик с номерами строк, переносом и копированием пути. Команда `files.read` отдаёт файл только изнутри проекта, не больше 512 KB, с замаскированными секретами; `read` с `offset` открывается на этой строке.
- Карточки тулов: подряд идущие `read`, `grep` и `glob` сворачиваются в шаг «Прочитал N файлов, искал M раз», упавший вызов раскрывает группу сам.
- Резервная модель видна: событие `model.fallback` пишет в лог провайдера, модель и причину, тред показывает заметку «Ответила резервная модель», окно даёт уведомление.
- Hooks: `failClosed` задаётся каждому хуку отдельно (переключатель «Блокировать при сбое»), падение, таймаут или битый ответ такого хука блокируют действие.
- Секреты маскируются в живом потоке событий, а не только в логе на диске: журнал событий маскирует событие до отправки в окно и до `events.replay`.
- `bun run verify` включает `docs:check`, добавлены `bun run docs:check` и `bun run coverage`.
- Исправлено: сохранённые события `context.usage`, `budget`, `approval.*`, `job.*`, `run.interrupted`, `model.fallback`, `provider.retry` и `notice.applied` писались в `events.jsonl`, но при открытии сессии отбрасывались как битые, поэтому после перезапуска пропадали шкала контекста, бюджет, подтверждения и фоновые задачи. Список читаемых типов теперь проверяет компилятор.
- Исправлено: раннер хуков игнорировал `failClosed` из конфига, сбой такого хука пропускал действие.
- Долг по правилам: regex в поведении заменён состоянием, структурными API и сканерами, устаревшие исключения ловит `check-rules`; baseline debt0, файлов длиннее500строк0. Неиспускаемые коды ошибок `not_implemented` и `tool_failed` удалены.

## 0.1.0

- Десктопный интерфейс переехал с одного HTML-прототипа на Svelte 5 и Vite.
- Появились компоненты окна, треда, композера, изменений, проверок и терминала.
- Electron shell грузит собранный интерфейс через `liquid://`.
- Добавлены `electron-builder`, CI и релизный workflow.
- Добавлена база агента: цикл, потоковые провайдеры, семь тулов и сессии.
- Добавлен ремонт аргументов тулов для маленьких моделей.
- Интерфейс подключён к ядру через sidecar на Bun.
- Демо-данные и заглушки удалены.
- CLI удалён: единственная точка входа это приложение.
- Добавлены Agent Skills с каталогом и активацией по запросу.
- Добавлены MCP tools через stdio и официальный client SDK.
- Добавлены command hooks на шести событиях сессии и тулов.
